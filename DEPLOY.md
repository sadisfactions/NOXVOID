# Публикация сайта: GitHub + Cloudflare Pages (для новичка)

Пошаговая инструкция. Ничего заранее создавать не нужно: аккаунты, репозиторий, база и секреты создаются по ходу.
Названия кнопок в Cloudflare и GitHub иногда меняются — если пункт называется чуть иначе, ищите похожий по смыслу.

**Схема.** Сайт и серверные функции лежат в репозитории GitHub. Cloudflare Pages берёт его оттуда и публикует.
Расписание хранится в базе Cloudflare D1. Пароль панели хранится в секретах Cloudflare.

> **Один клиент = один комплект:** свой репозиторий, свой проект Pages, своя база D1, свои секреты и пароль.
> Не подключайте две копии сайта к одной базе.

> **Важно:** загрузка папки перетаскиванием в браузере здесь не подходит — Cloudflare не собирает серверные функции при такой загрузке.
> Поэтому используется GitHub.

---

## Шаг 0. Перед началом

Заполните `public/config.js`: ник, ссылки, арт, тексты и блок `schedule` (часовой пояс и семь дней) — см. `SETUP.md`.
Из блока `schedule` потом создастся расписание в базе.

## Шаг 1. Установите Git

1. Скачайте Git для Windows: **https://git-scm.com/download/win** и установите, везде нажимая «Next».
2. Закройте и заново откройте VS Code (или терминал).
3. Проверьте: `git --version` — должна появиться версия.
4. Один раз укажите, кто вы (вместо слов в кавычках впишите своё):
   ```
   git config --global user.name "Ваше Имя"
   git config --global user.email "ваша-почта@example.com"
   ```

## Шаг 2. Аккаунт GitHub и репозиторий

1. Зарегистрируйтесь на **https://github.com** (кнопка «Sign up»). Включите двухфакторную защиту.
2. Нажмите значок «+» в правом верхнем углу → **New repository**.
3. Имя — любое понятное, например `site-имя-клиента`. Выберите **Private**. Галочки «Add a README» **не ставьте**.
4. Нажмите **Create repository** и скопируйте адрес репозитория (вида `https://github.com/логин/имя.git`).

## Шаг 3. Загрузите проект в репозиторий

В терминале, находясь в папке проекта `GLITCH-CORE`, выполните по очереди (вместо адреса впишите свой):

```
git init
git add .
git commit -m "Первая версия"
git branch -M main
git remote add origin https://github.com/ЛОГИН/ИМЯ.git
git push -u origin main
```

При `git push` откроется окно входа в GitHub — войдите. После этого обновите страницу репозитория на GitHub: там должны появиться файлы.
Проверьте, что в репозитории **нет** папок `node_modules` и файла `.dev.vars` (они исключены через `.gitignore`).

## Шаг 4. Аккаунт Cloudflare

Зарегистрируйтесь на **https://dash.cloudflare.com/sign-up** (бесплатный тариф подходит). Подтвердите почту, включите двухфакторную защиту.

> Бесплатный тариф: до 10 баз D1 и 100 000 запросов к функциям в сутки на аккаунт (статические файлы не считаются).
> Эти лимиты общие для всех проектов в аккаунте, поэтому для нескольких клиентов лучше отдельный аккаунт у каждого.
> Актуальные лимиты смотрите в документации Cloudflare.

## Шаг 5. Создайте базу D1

1. В панели Cloudflare откройте страницу **D1 SQL database** и нажмите **Create Database**.
2. Имя — например, `glitch-core-имя-клиента`. Нажмите **Create**.
3. Откройте созданную базу → вкладка **Console**.
4. Откройте на своём компьютере файл `migrations/0001_init.sql`, скопируйте всё содержимое, вставьте в Console и нажмите **Execute**.
5. Повторите то же для файла `migrations/0002_status_cache.sql` (кэш статуса Twitch; безопасно: только добавляет таблицу).
6. Откройте **Tables**: должны быть таблицы `schedule`, `login_attempts` и `kv`.

   Если база уже создана раньше (миграция `0001` выполнена), выполните **только** `0002` — данные расписания не затрагиваются.
   То же из терминала (для существующей базы подставьте её имя, например `noxvoid-db`; нужен вход через `npx wrangler login`):
   ```
   npx wrangler d1 execute noxvoid-db --remote --file=migrations/0002_status_cache.sql
   ```

## Шаг 6. Создайте проект Pages и подключите GitHub

1. Откройте **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**.
2. Выберите **GitHub**, авторизуйтесь, нажмите **Install & Authorize** и разрешите доступ к вашему репозиторию.
3. Выберите репозиторий → **Begin setup**.
4. Настройки:
   - **Project name** — это будет адрес `имя.pages.dev`;
   - **Production branch** — `main`;
   - **Framework preset** — `None`;
   - **Build command** — `exit 0`;
   - **Build output directory** — `public`.
5. Нажмите **Save and Deploy**. Первая публикация завершится, но панель управления пока не заработает — нужны следующие два шага.

## Шаг 7. Привяжите базу к проекту

1. Откройте проект → **Settings** → **Bindings** → **Add** → **D1 database bindings**.
2. **Variable name** — строго `DB` (заглавными). **D1 database** — выберите созданную базу. Сохраните.

## Шаг 8. Задайте секреты (пароль панели)

1. Проект → **Settings** → **Variables and Secrets** → **Add**.
2. Добавьте два значения, у каждого выберите тип/галочку **Encrypt** (секрет):

   | Имя | Что вписать |
   |---|---|
   | `ADMIN_PASSWORD` | Длинный пароль для входа в панель (лучше 16+ символов) |
   | `SESSION_SECRET` | Случайная строка от 32 символов (см. ниже) |

   Чтобы получить случайную строку, выполните в терминале:
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
3. Нажмите **Save**. Пароль не пишите в файлы проекта и не отправляйте в открытом чате.

## Шаг 9. Опубликуйте заново, чтобы привязка и секреты заработали

Откройте проект → **Deployments** → у последней публикации выберите **Retry deployment**
(либо внесите любую правку в репозиторий — публикация запустится сама).

## Шаг 10. Проверьте

1. Откройте `https://имя.pages.dev` — сайт должен открыться.
2. Откройте `https://имя.pages.dev/admin`, введите пароль.
3. Нажмите **«Создать расписание из config.js»**. Появится панель с ближайшим стримом.
4. Проверьте: перенесите стрим, затем нажмите «Вернуть исходное»; обновите сайт — расписание должно соответствовать панели.
5. Передайте клиенту адрес `/admin` и пароль **отдельно** от остального (и файл `README.md` из проекта).

Если Cloudflare не видит папку `functions` (панель отвечает «серверная часть недоступна») — проверьте, что `functions` лежит в корне репозитория,
а не внутри `public`, и сделайте повторную публикацию.

## Шаг 11 (по желанию). Автоматический статус «В эфире» через Twitch

Без этого шага всё работает: статус переключается вручную в панели. С ним сайт сам узнаёт, идёт ли трансляция.
Настоящий Twitch из локальной среды проверить нельзя — после настройки проверьте на опубликованном сайте (пункт 6 ниже).

1. Откройте **https://dev.twitch.tv/console** → войдите своим аккаунтом Twitch (нужна двухфакторная защита Twitch) → **Register Your Application**.
2. **Name** — любое уникальное; **OAuth Redirect URLs** — `http://localhost`; **Category** — Website Integration; **Client Type** — **Confidential**. Нажмите **Create**.
3. Откройте созданное приложение → **Manage**: скопируйте **Client ID**, нажмите **New Secret** и скопируйте **Client Secret** (показывается один раз).
4. В Cloudflare: проект → **Settings** → **Variables and Secrets** → добавьте (для Production):

   | Имя | Значение | Тип |
   |---|---|---|
   | `TWITCH_CLIENT_ID` | Client ID | Secret или Text |
   | `TWITCH_CLIENT_SECRET` | Client Secret | **Secret (Encrypt)** |
   | `TWITCH_LOGIN` | логин канала на Twitch (как в адресе `twitch.tv/логин`) | Text |
5. Опубликуйте заново (шаг 9).
6. В панели `/admin` → блок «Статус трансляции» → кнопка **«Twitch (авто)»**. Должно появиться «Проверено в ЧЧ:ММ:СС». Начните трансляцию на Twitch — в течение 1–2 минут сайт покажет «В ЭФИРЕ».

Как это работает: сервер раз в минуту спрашивает Twitch (не браузеры посетителей) и кэширует ответ в базе. Если Twitch недоступен, сайт показывает последний
полученный результат (до 10 минут), затем «Статус уточняется» — но не «не в эфире». Секрет нигде не попадает в браузер.
Если ключи неверные, панель покажет «Twitch отклонил ключи приложения». Вернуться к ручному режиму можно кнопкой «Вручную».

## Свой домен (по желанию)

Проект → **Custom domains** → добавьте домен и следуйте подсказкам Cloudflare.

## Как обновлять сайт

Изменили файл (например, ссылки в `public/config.js`) — в терминале:

```
git add .
git commit -m "Обновил ссылки"
git push
```

Cloudflare сам опубликует новую версию через минуту-две. Расписание от этого не меняется: оно хранится в базе.

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| В панели «Серверная часть недоступна» | Нет папки `functions` в корне репозитория или не было повторной публикации после шагов 7–8 |
| «Хранилище недоступно» | Не выполнена миграция (шаг 5), привязка названа не `DB` (шаг 7) или нужна повторная публикация (шаг 9) |
| «Панель не настроена: задайте секреты…» | Не заданы `ADMIN_PASSWORD` / `SESSION_SECRET` или `SESSION_SECRET` короче 16 символов (шаг 8), либо нет повторной публикации |
| «Неверный пароль» | Проверьте `ADMIN_PASSWORD`. После 5 ошибок подряд вход блокируется на 15 минут |
| «Расписание ещё не создано» | Нажмите «Создать расписание из config.js» |
| Режим Twitch: «Twitch не настроен» | Не заданы `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `TWITCH_LOGIN` или не было повторной публикации (шаг 11) |
| «Статус уточняется» на сайте | Twitch временно недоступен или не выполнена миграция `0002` (создаёт таблицу `kv`) |
| Нужно сменить пароль | Измените значение `ADMIN_PASSWORD` в Variables and Secrets и опубликуйте заново. Чтобы выйти со всех устройств, смените и `SESSION_SECRET` |
| Расписание создали с неверным часовым поясом | В Cloudflare: D1 → ваша база → Console → выполните `DELETE FROM schedule;`, поправьте `timezone` в `public/config.js`, загрузите (`git push`) и снова нажмите «Создать расписание из config.js» |

## Локальный запуск и проверки (для разработчика)

Нужен установленный Node.js. Выполняйте из папки проекта.

```
npm install                                  (один раз)
copy .dev.vars.example .dev.vars             (впишите свои тестовые значения паролей)
npm run db:local                             (создаёт таблицы в локальной базе)
npm run dev                                  (сайт и панель на http://127.0.0.1:8788, /admin/)
npm test                                     (быстрые проверки логики и входа)
npm run test:local                           (проверки API; нужен запущенный npm run dev)
npm run test:twitch                          (проверки статуса Twitch на поддельном Twitch; в .dev.vars добавьте строки TWITCH_* из .dev.vars.example,
                                              значения: TWITCH_CLIENT_ID=mock-client, TWITCH_CLIENT_SECRET=mock-secret, TWITCH_LOGIN=noxvoid и два адреса http://127.0.0.1:8799)
```

`npm run db:local` выполняет обе миграции. Пароль `test-pass-123` встречается только в автотестах и на опубликованный сайт не попадает.

Локальная база хранится в папке `.wrangler` и не имеет отношения к настоящей на Cloudflare.
