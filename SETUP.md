# GLITCH//CORE — настройка сайта под клиента (для продавца)

Эта инструкция для того, кто настраивает сайт. Клиенту отдаётся короткий `README.md` — там только про панель управления расписанием.
Как выложить сайт в интернет — в `DEPLOY.md`.

Сайт: первый экран — «постер» (ник, арт героя, кнопки, расписание), ниже при прокрутке идут секции «О стримере» и «Лучшие моменты».
Расписание и статус «В эфире» клиент меняет сам в панели `/admin`. Всё остальное (ник, ссылки, арт, тексты, цвета) настраиваете вы в одном файле — **`public/config.js`**.

---

## Что в папке

| Путь | Для чего |
|---|---|
| `public/config.js` | **Данные клиента: ник, ссылки, тексты, цвета, начальное расписание** |
| `public/index.html`, `styles.css`, `script.js` | Сайт. Не трогайте |
| `public/assets/` | Картинки. Сюда кладёте арт героя |
| `public/admin/` | Панель управления (страница `/admin`) |
| `functions/` | Серверная часть (Cloudflare Pages Functions): API расписания и вход в панель |
| `migrations/` | SQL для создания таблиц в базе D1 (`0001` — расписание и вход, `0002` — кэш статуса Twitch) |
| `scripts/brand.mjs` | `npm run brand`: переносит заголовок и мета-теги из `config.js` в `index.html` (см. 5a) |
| `tests/` | Автоматические проверки |
| `DEPLOY.md` | Пошаговая публикация: GitHub + Cloudflare Pages |
| `README.md` | Памятка для клиента |

Папку `public/` публикуют как сайт, остальное остаётся вне сайта и посетителям недоступно.

## 1. Как посмотреть сайт у себя

- **Только внешний вид** (без панели управления): откройте `public/index.html` двойным щелчком. Расписание в этом случае берётся из `config.js`.
- **Вместе с панелью и базой** (локально): см. раздел «Локальный запуск» в `DEPLOY.md`.

## 2. Как править `public/config.js`

Щёлкните по файлу правой кнопкой → «Открыть с помощью» → «Блокнот». Меняйте только то, что внутри кавычек `"..."`.
Кавычки, запятые и скобки не удаляйте. Сохраните: `Ctrl + S`.
Если сайт «сломался» (пустая страница) — потерялась кавычка или запятая, верните как было.

## 3. Ник, слоган, ссылки

```js
nickname: "NOXVOID",
category: "СТРИМЕР DOTA 2",
slogan: "NO META. NO MERCY.",
rank: "РАНГ: БЕССМЕРТНЫЙ",
```

Ссылки (замените `your_channel` на реальные адреса; пустые кавычки `""` — пункт пропадёт из меню):

```js
links: {
  twitch:   "https://www.twitch.tv/your_channel",
  youtube:  "https://www.youtube.com/@your_channel",
  telegram: "https://t.me/your_channel",
  discord:  "https://discord.gg/your_invite",
  donate:   "https://www.donationalerts.com/r/your_channel",
  boosty:   "https://boosty.to/your_channel",
},
```

Окна «Мои сети» и «Поддержать» берут ссылки отсюда; если все ссылки окна пустые, окно будет пустым.

Сейчас в `config.js` стоят **демо-адреса** — главные страницы платформ (twitch.tv, youtube.com и т. д.): они открываются, но не принадлежат стримеру.
Перед передачей клиенту замените их на его адреса. Ссылка с пустым значением или с «your_channel» / «your_invite» на сайте не показывается
(кнопка скрывается, пункт в окне исчезает), поэтому «мёртвых» кнопок не будет. Карточка «Лучших моментов» без адреса (`url` и `links.highlights` пусты) остаётся просто картинкой.
Блок `about.facts` и список `highlights` тоже демонстрационные: пометки «ДЕМО-ДАННЫЕ» уберёт `demo: false` после замены.

## 4. Арт героя

1. Положите картинку в `public/assets/`, например `hero.webp`.
2. В `config.js`: `heroImage: "assets/hero.webp",` и `heroAlt` (описание картинки для скринридеров).
3. Если у героя светятся глаза, укажите их положение в долях картинки: `heroEyes: { x: 0.694, y: 0.167 }` (x — слева направо, y — сверху вниз).
   Подсветка и парение включаются сами; если глаз нет, удалите строку `heroEyes`.
4. Также замените картинку превью ссылки `assets/og.jpg` и в `public/index.html` блок `<link rel="icon">` при необходимости (см. 5a).

Лучше всего WebP или PNG с **прозрачным фоном** (вырезанный герой), около 1000–1300 px по ширине, до 400 КБ.
Если фон чёрный (как у исходника «Призрака Бездны»), его нужно сделать прозрачным, иначе на сайте будет видна рамка.
Используйте только то, на что у вас есть права. Сейчас стоит «Призрак Бездны» (`assets/abyss-wraith-refined.webp`): тело плотное, а широкие внутренние полости прозрачны, через них виден фон сайта. Резервные копии: `assets/abyss-wraith-open.webp` (прозрачных участков больше), `assets/abyss-wraith.webp` (те же участки залиты чёрным) и `assets/hero-placeholder.svg`.

## 5. Секции, тексты, цвета

```js
sections: { about: true, highlights: true },   // false — убрать секцию
```

Тексты «О стримере» — блок `about`, названия клипов — блок `highlights` (у клипа можно задать ссылку в `url`).
Все цифры и названия в шаблоне демонстрационные. Пометки «ДЕМО-ДАННЫЕ» у секций убирает `demo: false`,
а надпись в правом верхнем углу — это `statusText`.
Цвета: `colors: { accent: "#C6FF00", accent2: "#B52CFF" }`.

## 5a. Заголовок, превью ссылки (SEO) и шрифты

Заголовок и мета-теги задаются в `config.js` (`siteUrl` и блок `seo`), а в `public/index.html` их переносит команда:

```
npm run brand            # обновляет index.html и перечисляет, что изменилось
npm run brand -- --check # только проверка: ничего не пишет, код 1, если index.html расходится с config.js
```

Она заполняет `<title>`, `description`, `canonical`, `og:*`, `twitter:*`, ник в шапке и в заголовке. Если не хватает `nickname`, `siteUrl` или `seo.*`, либо `siteUrl` не похож на адрес (`https://…/`), команда сообщает об ошибке и ничего не меняет.
Запускайте её после правки `config.js`, до коммита (Cloudflare Pages публикует `public/` как есть, на его стороне ничего не запускается).
Адрес в `siteUrl` — тот, по которому сайт реально открывается (`*.pages.dev` или свой домен): по нему строится ссылка на картинку превью.

- Картинка превью ссылки (Telegram, Discord, VK и др.) — `public/assets/og.jpg`, 1200×630, до 300 КБ. Для другого стримера сделайте свою с ником.
  После публикации превью кэшируется соцсетями: обновить его можно в их отладчиках (например, Telegram — бот @WebpageBot).
- `public/assets/favicon.svg` и `apple-touch-icon.png` — значок сайта; `public/robots.txt` закрывает `/admin/` и `/api/` от поисковиков.
- Текст внизу страницы — `footer` в `config.js`.
- Заголовки используют шрифт Impact; там, где его нет (Android, Linux), подключается Oswald из `public/assets/fonts/` (лицензия SIL OFL 1.1).
  Файлы шрифтов не удаляйте.
- Несуществующие адреса показывают страницу `public/404.html`.

## 5b. Фон «призрачное пространство»

За интерфейсом и персонажем лежит живой декоративный фон: фиолетовая дымка и туман, а также 15 тёмных существ (9 на телефоне) с едва заметными глазами.
Существа очень медленно и независимо плавают, слегка приближаются и удаляются. Настроек в `config.js` у фона нет.

**Из чего состоит**
- `index.html`: блок `<div class="bg-space">` в начале `<body>` (дымка, туман, виньетка и холст `<canvas class="bg-ghosts">`) и два скрипта в конце.
- `bg-ghosts.js`: движение, реакции на курсор и клики, редкие глитчи (один цикл `requestAnimationFrame`, без библиотек). Сверху файла в блоке `CFG` собраны основные настройки (радиус и сила отталкивания, шанс «замереть», частота глитчей, разрешение холста).
- `assets/bg/ghosts-atlas.webp` (спрайты существ, около 440 КБ) и `assets/bg/ghosts-data.js` (их размеры и раскладки для компьютера и телефона); `fog.webp`, `fog-2.webp` (туман).
- `styles.css`: блок «Фон: призрачное пространство» в конце файла.

**Поведение**
- Курсор мыши мягко отталкивает ближайших существ и не блокирует клики по интерфейсу; на телефоне отталкивание выключено.
- Клик (касание) по самому существу, не по тексту, кнопке или персонажу: вспышка глаз, RGB-глитч, бегство, растворение в дымке, возвращение в другом месте (вне текста и кнопок). Редко существо вместо бегства замирает и «наблюдает». Не более трёх одновременно.
- Раз в 7–17 секунд случается короткий глитч одного существа или тонкие цифровые полосы. Заголовок и главный персонаж не искажаются.
- Фон подгружается после основной страницы и плавно проявляется. При включённой в системе настройке «уменьшить движение» (`prefers-reduced-motion`) он статичен и интерактивность выключена. В скрытой вкладке цикл останавливается.

**Как изменить**
- Убрать фон целиком: удалите блок `<div class="bg-space">…</div>` и два тега `<script>` с `ghosts-data.js` и `bg-ghosts.js` в `index.html`. Остальной сайт от этого не зависит.
- Выключить только интерактивность и оставить статичный фон: уберите тег `<script src="bg-ghosts.js">`; тогда останутся дымка и туман без существ.
- Атлас и раскладки созданы генератором (это не стоковые изображения и не копии референса); при замене картинок обновите и `ghosts-data.js`.
- Нагрузка: на слабых устройствах можно уменьшить `scale` в `CFG` (разрешение холста) или увеличить `idleMs`. Заметную долю нагрузки даёт и CSS-туман (слои `.bg-fog` с `mix-blend-mode: screen`): если нужно ещё легче, уберите один из двух слоёв тумана в `index.html`.
- Замеры скорости делались в headless Edge с программным (без видеокарты) рендером: 44 к/с с живым фоном против 61 без него. На компьютере с видеокартой разница обычно меньше, но это не измерялось.
- Клик по существу использует карту прозрачности атласа; при открытии `index.html` как обычного файла (`file://`) она недоступна, и срабатывает только клик по «голове».

## 6. Расписание: как это устроено

Расписание хранится **в базе (Cloudflare D1)**, а не в файле. Клиент меняет его в панели `/admin`: переносы, отмены,
регулярные дни и время, статус «В эфире». Публикация сайта заново для этого не нужна.

Что делает `schedule` в `config.js` теперь:
- **Начальное расписание.** При первом входе в панель кнопка «Создать расписание из config.js» переносит его в базу. Заполните блок `schedule` (часовой пояс, семь дней) **до** этого шага.
- **Запасной вариант.** Если база недоступна (или сайт открыт как обычный файл), сайт показывает расписание из `config.js`.

После создания расписания в базе правка блока `schedule` в `config.js` на сайт **не влияет** — расписание меняют только в панели.

**Часовой пояс** тоже хранится в базе и при первом создании берётся из `config.js` (`timezone`, `timezoneLabel`).
Хранение рассчитано на то, чтобы в будущем менять его из панели без правки файлов; сейчас такой кнопки в панели нет.

**Статус «В эфире»** не зависит от расписания и имеет два источника (клиент выбирает в панели):
- **Вручную** — переключатель в панели (режим по умолчанию, работает без настройки).
- **Twitch (авто)** — проверка канала на сервере через Twitch API. Нужны секреты `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` и `TWITCH_LOGIN`
  (инструкция — `DEPLOY.md`, шаг 11). Пока они не заданы, панель честно пишет, что автоматический режим не настроен.
Ключи Twitch у каждого клиента свои (его приложение на dev.twitch.tv или ваше — но тогда секрет лежит у вас; лучше клиенту завести своё).

> Блок `overrides` в `config.js` нужен только как часть начального расписания. Разовые переносы клиент делает в панели.

## 7. Безопасность и разные клиенты

- Пароль панели хранится в секретах Cloudflare (`ADMIN_PASSWORD`), а не в файлах сайта. Передавайте его клиенту отдельно от сайта.
- **Каждому клиенту — свой комплект:** свой репозиторий, свой проект Cloudflare Pages, своя база D1, свои секреты и свой пароль.
  Не подключайте две копии сайта к одной базе и не используйте один пароль.
- Лучше, чтобы аккаунты (GitHub и Cloudflare) принадлежали клиенту. Если они ваши — включите двухфакторную защиту.
- Не отдавайте клиенту папки `node_modules`, `.wrangler` и файл `.dev.vars` (они нужны только для локальной проверки).

## 8. Чек-лист: подготовка сайта для нового стримера

1. **Имя и тексты** (`config.js`): `nickname`, `category`, `slogan`, `rank`, `playerId`, `bioShort`, `footer`, блок `about`, названия в `highlights`.
2. **SEO** (`config.js`): `siteUrl` (реальный адрес сайта), `seo.title`, `seo.description`, `seo.shareDescription`. Затем `npm run brand` и проверка `npm run brand -- --check`.
3. **Соцсети и ссылки**: заполните `links` (Twitch, YouTube, Telegram, Discord, донаты), проверьте каждую в браузере; у клипов задайте `url` или уберите секцию (`sections.highlights: false`).
4. **Расписание**: часовой пояс, семь дней, время. После публикации один раз «Создать расписание из config.js» в `/admin`.
5. **Изображения** (вручную, скрипт их не трогает): арт героя (`heroImage`, `heroAlt`, `heroEyes`), `assets/og.jpg` с ником клиента (1200×630), `favicon.svg` и `apple-touch-icon.png`. Лишние резервные копии арта удалите.
6. **Цвета**: `colors` действуют не везде: часть оттенков в `styles.css` и `bg-ghosts.js` зашита, тени фона-призраков запечены в атласе. Для другой палитры проверьте весь сайт глазами.
7. **Демо-пометки**: замените демо-данные и поставьте `demo: false`, обновите `statusText`.
8. **Проверка перед публикацией**: `npm test`; открыть сайт на телефоне или в режиме мобильного экрана (360–414 px): нет горизонтальной прокрутки, первый экран умещается, окна «Мои сети» и «Поддержать» открываются и закрываются (Esc, кнопка), все кнопки ведут на нужные адреса.
9. **После публикации**: проверить заголовок вкладки и превью ссылки (Telegram, Discord), вход в `/admin`, перенос и отмену стрима; пароль и секреты передать клиенту отдельно.

## Частые вопросы

**Изменил `public/config.js`, а на сайте ничего не поменялось.**
Обновите страницу с очисткой кэша (`Ctrl + F5`). Если сайт на Cloudflare — файл нужно загрузить в репозиторий (см. `DEPLOY.md`, раздел «Как обновлять сайт»).

**Расписание в панели и в `config.js` разное.**
Так и должно быть после создания расписания в базе: главное — то, что в панели.

**Часы в расписании не те.**
Часовой пояс (`timezone`) задаётся при создании расписания. Если указан неверный — потребуется пересоздать расписание (см. `DEPLOY.md`, «Если что-то пошло не так»).
