# GLITCH//CORE — настройка сайта под клиента (для продавца)

Эта инструкция для того, кто настраивает сайт. Клиенту отдаётся короткий `README.md` — там только про панель управления расписанием.
Как выложить сайт в интернет — в `DEPLOY.md`.

Сайт: первый экран — «постер» (ник, арт героя, кнопки, расписание), ниже при прокрутке идут секции «О стримере» и «Лучшие моменты».
Расписание и статус «В эфире» клиент меняет сам в панели `/admin`. Всё остальное (ник, ссылки, арт, тексты, цвета) настраиваете вы в одном файле — **`public/config.js`**.

---

## Что в папке

| Путь | Для чего |
|---|---|
| `public/config.js` | **Данные клиента: ник, ссылки, тексты, цвета, начальное расписание** |
| `public/index.html`, `styles.css`, `script.js` | Сайт. Не трогайте |
| `public/assets/` | Картинки. Сюда кладёте арт героя |
| `public/admin/` | Панель управления (страница `/admin`) |
| `functions/` | Серверная часть (Cloudflare Pages Functions): API расписания и вход в панель |
| `migrations/` | SQL для создания таблиц в базе D1 (`0001` — расписание и вход, `0002` — кэш статуса Twitch) |
| `tests/` | Автоматические проверки |
| `DEPLOY.md` | Пошаговая публикация: GitHub + Cloudflare Pages |
| `README.md` | Памятка для клиента |

Папку `public/` публикуют как сайт, остальное остаётся вне сайта и посетителям недоступно.

## 1. Как посмотреть сайт у себя

- **Только внешний вид** (без панели управления): откройте `public/index.html` двойным щелчком. Расписание в этом случае берётся из `config.js`.
- **Вместе с панелью и базой** (локально): см. раздел «Локальный запуск» в `DEPLOY.md`.

## 2. Как править `public/config.js`

Щёлкните по файлу правой кнопкой → «Открыть с помощью» → «Блокнот». Меняйте только то, что внутри кавычек `"..."`.
Кавычки, запятые и скобки не удаляйте. Сохраните: `Ctrl + S`.
Если сайт «сломался» (пустая страница) — потерялась кавычка или запятая, верните как было.

## 3. Ник, слоган, ссылки

```js
nickname: "NOXVOID",
category: "СТРИМЕР DOTA 2",
slogan: "NO META. NO MERCY.",
rank: "РАНГ: БЕССМЕРТНЫЙ",
```

Ссылки (замените `your_channel` на реальные адреса; пустые кавычки `""` — пункт пропадёт из меню):

```js
links: {
  twitch:   "https://www.twitch.tv/your_channel",
  youtube:  "https://www.youtube.com/@your_channel",
  telegram: "https://t.me/your_channel",
  discord:  "https://discord.gg/your_invite",
  donate:   "https://www.donationalerts.com/r/your_channel",
  boosty:   "https://boosty.to/your_channel",
},
```

Окна «Мои сети» и «Поддержать» берут ссылки отсюда; если все ссылки окна пустые, окно будет пустым.

## 4. Арт героя

1. Положите картинку в `public/assets/`, например `hero.png`.
2. В `config.js`: `heroImage: "assets/hero.png",`

Лучше всего PNG или WebP с прозрачным фоном (вырезанный герой), около 1000×1300 пикселей.
Используйте только то, на что у вас есть права. Сейчас стоит временная заглушка.

## 5. Секции, тексты, цвета

```js
sections: { about: true, highlights: true },   // false — убрать секцию
```

Тексты «О стримере» — блок `about`, названия клипов — блок `highlights` (у клипа можно задать ссылку в `url`).
Все цифры и названия в шаблоне демонстрационные. Пометки «ДЕМО-ДАННЫЕ» у секций убирает `demo: false`,
а надпись в правом верхнем углу — это `statusText`.
Цвета: `colors: { accent: "#C6FF00", accent2: "#B52CFF" }`.

## 6. Расписание: как это устроено

Расписание хранится **в базе (Cloudflare D1)**, а не в файле. Клиент меняет его в панели `/admin`: переносы, отмены,
регулярные дни и время, статус «В эфире». Публикация сайта заново для этого не нужна.

Что делает `schedule` в `config.js` теперь:
- **Начальное расписание.** При первом входе в панель кнопка «Создать расписание из config.js» переносит его в базу. Заполните блок `schedule` (часовой пояс, семь дней) **до** этого шага.
- **Запасной вариант.** Если база недоступна (или сайт открыт как обычный файл), сайт показывает расписание из `config.js`.

После создания расписания в базе правка блока `schedule` в `config.js` на сайт **не влияет** — расписание меняют только в панели.

**Часовой пояс** тоже хранится в базе и при первом создании берётся из `config.js` (`timezone`, `timezoneLabel`).
Хранение рассчитано на то, чтобы в будущем менять его из панели без правки файлов; сейчас такой кнопки в панели нет.

**Статус «В эфире»** не зависит от расписания и имеет два источника (клиент выбирает в панели):
- **Вручную** — переключатель в панели (режим по умолчанию, работает без настройки).
- **Twitch (авто)** — проверка канала на сервере через Twitch API. Нужны секреты `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` и `TWITCH_LOGIN`
  (инструкция — `DEPLOY.md`, шаг 11). Пока они не заданы, панель честно пишет, что автоматический режим не настроен.
Ключи Twitch у каждого клиента свои (его приложение на dev.twitch.tv или ваше — но тогда секрет лежит у вас; лучше клиенту завести своё).

> Блок `overrides` в `config.js` нужен только как часть начального расписания. Разовые переносы клиент делает в панели.

## 7. Безопасность и разные клиенты

- Пароль панели хранится в секретах Cloudflare (`ADMIN_PASSWORD`), а не в файлах сайта. Передавайте его клиенту отдельно от сайта.
- **Каждому клиенту — свой комплект:** свой репозиторий, свой проект Cloudflare Pages, своя база D1, свои секреты и свой пароль.
  Не подключайте две копии сайта к одной базе и не используйте один пароль.
- Лучше, чтобы аккаунты (GitHub и Cloudflare) принадлежали клиенту. Если они ваши — включите двухфакторную защиту.
- Не отдавайте клиенту папки `node_modules`, `.wrangler` и файл `.dev.vars` (они нужны только для локальной проверки).

## Частые вопросы

**Изменил `public/config.js`, а на сайте ничего не поменялось.**
Обновите страницу с очисткой кэша (`Ctrl + F5`). Если сайт на Cloudflare — файл нужно загрузить в репозиторий (см. `DEPLOY.md`, раздел «Как обновлять сайт»).

**Расписание в панели и в `config.js` разное.**
Так и должно быть после создания расписания в базе: главное — то, что в панели.

**Часы в расписании не те.**
Часовой пояс (`timezone`) задаётся при создании расписания. Если указан неверный — потребуется пересоздать расписание (см. `DEPLOY.md`, «Если что-то пошло не так»).
